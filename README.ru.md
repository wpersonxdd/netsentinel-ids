# NetSentinel: руководство на русском

Это ваш проект для задачи **DN-CY-01 «Network Intrusion Detection with Imbalanced Threat Data»** хакатона
DataNova 2026. Основной `README.md` написан на английском для международного жюри. Этот файл объясняет проект
вам: как он устроен, как его запускать и как о нём рассказывать.

---

## 1. Что делает проект, простыми словами

Сетевой трафик разбит на **потоки** (flows): одно соединение между двумя компьютерами с его статистикой (сколько
пакетов, байт, длительность, флаги TCP и т.д.). Задача: по этой статистике понять, обычный это трафик или атака,
и какая именно.

Есть четыре трудности, и проект решает каждую:

| Трудность | Решение в проекте |
|---|---|
| **Дисбаланс**: 80% трафика обычный, а редкой атаки всего 0.15%. Модель может «угадывать» всё как обычное и иметь 80% точности | Сравнение 4 стратегий (веса классов, SMOTE, undersampling + SMOTE) на 5 моделях; метрики, которые не обманываются дисбалансом (macro-F1, PR-AUC) |
| **Новые атаки**: модель знает только те атаки, на которых училась | Второй детектор (LOF) учится только на обычном трафике и ловит всё «непохожее на норму» → метка `Unknown-Anomaly` |
| **Атаки меняются со временем** (drift) | Эксперимент «учимся на прошлом, проверяем на будущем»; монитор дрейфа без разметки; дообучение на метках аналитика |
| **Модель должна учиться на работе аналитиков** | Каждое решение аналитика сохраняется вместе с признаками потока, то есть это готовый обучающий пример. Команда `nids retrain` (или кнопка в интерфейсе) дообучает модель, честно сравнивает старую и новую на непросмотренных потоках, ставит новую, а старую архивирует |
| **Человеку нужен понятный результат** | Тысячи оповещений по отдельным потокам сгруппированы в **инциденты** (тот же тип атаки + общий узел + время). Интерфейс аналитика: очередь P1–P4, объяснение «почему», рекомендация «что делать», одно решение аналитика размечает весь инцидент |

## 2. Как запустить (Windows)

Откройте PowerShell или терминал в папке `C:\Users\user\Projects\netsentinel-ids`.

**Окружение уже создано** (папка `.venv`). Если будете ставить на другом компьютере:

```bash
py -3.11 -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

```bash
.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

```bash
.venv\Scripts\python.exe -m pip install -e . --no-deps
```

**Полный прогон** (генерация данных → сравнение моделей → финальная модель → новые атаки → дрейф → отчёт),
около 15 минут:

```bash
.venv\Scripts\python.exe -m nids all
```

**Интерфейс аналитика** (откроется в браузере):

```bash
.venv\Scripts\python.exe -m streamlit run app/streamlit_app.py
```

**Тесты:**

```bash
.venv\Scripts\python.exe -m pytest -q
```

Отдельные шаги: `generate-data`, `benchmark`, `train`, `novelty`, `drift`, `report`, `score`,
`simulate-feedback`, `retrain`.

**Дообучение на решениях аналитика.** Разберите несколько инцидентов в интерфейсе (кнопка «Save decision»), затем
нажмите внизу очереди «Retrain model with analyst feedback» или выполните:

```bash
.venv\Scripts\python.exe -m nids retrain
```

Новая модель заменит старую, а старая уйдёт в `artifacts/model_history/`.
Справка: `.venv\Scripts\python.exe -m nids --help`.

## 4. ВАЖНО: про синтетические данные

Официальный датасет хакатона ещё не опубликован. Поэтому проект генерирует **синтетические** данные, похожие на
CIC-IDS2017: с дисбалансом, «маскирующимися» атаками, шумом в разметке и дрейфом. Все цифры в `reports/REPORT.md`
сейчас относятся к ним. В отчёте об этом стоит пометка.

**Никогда не выдавайте эти цифры за результаты на реальных данных.** Когда выйдет официальный датасет:

```bash
.venv\Scripts\python.exe -m nids all --data data/raw/official
```

Всё пересчитается автоматически, пометка про синтетику исчезнет. Подробности в `docs/DATASET.md`.

Потренироваться на реальных данных можно уже сейчас на CIC-IDS2017 или UNSW-NB15 (ссылки в `docs/DATASET.md`).
Код работает с ними без изменений. Совет: прогоните на UNSW-NB15 до выхода официальных данных, тогда на
вопрос «а на реальных данных работает?» у вас будет ответ.

## 5. Пять идей, которые надо донести жюри

1. **«Accuracy здесь врёт».** Модель, которая всегда говорит «норма», даёт 80% accuracy и 0% обнаружения атак.
   Поэтому мы оцениваем macro-F1, F1 на редких классах и PR-AUC.
2. **«Мы честно измерили, что даёт борьба с дисбалансом».** Одна и та же модель с SMOTE и без него на одном
   тестовом наборе. Прирост на редких классах виден в таблице и на графике `per_class_f1.png`.
3. **«Система замечает атаки, которых не видела».** Эксперимент leave-one-attack-out: убираем атаку из обучения и
   смотрим, поднимется ли тревога. Плюс сравнение трёх детекторов аномалий: LOF оказался в разы лучше Isolation Forest.
4. **«Мы замечаем, когда модель устаревает, даже без разметки».** Дрейф среди потоков с оповещениями, сдвиг доли
   предсказаний, рост `Unknown-Anomaly`. Дообучение на 10% размеченных новых данных возвращает качество.
5. **«Это продукт, а не ноутбук».** Оповещения группируются в инциденты (в разы меньше работы аналитику), интерфейс
   с приоритетами, объяснениями и рекомендациями. Плюс тесты, CI, Docker и одна команда для полного прогона.
6. **«Цикл замкнут».** Решения аналитика — это размеченные примеры. Модель дообучается на них, а сравнение старой и
   новой версии идёт только на потоках, которые никто не просматривал, иначе результат был бы нечестно завышен.
   В отчёте (§8) показан эффект одного «рабочего дня» симулированного аналитика.

И честно про ограничения (жюри это ценит): атаки, которые выглядят как обычный трафик (web-атаки внутри нормальных
HTTP-сессий), на уровне статистики потоков ловятся плохо. Это ограничение признаков, и в отчёте оно так и описано.

## 6. Словарь: что надо уметь объяснить своими словами

| Термин | Простое объяснение |
|---|---|
| **Дисбаланс классов** | Одних примеров намного больше, чем других. Модель «ленится» и учит только частые |
| **SMOTE** | Создаёт новые искусственные примеры редкого класса «между» существующими (интерполяция между соседями). Только в обучающих данных! |
| **Undersampling** | Выбрасываем часть примеров частого класса |
| **Class weights** | Ошибка на редком классе «стоит дороже» при обучении |
| **Focal loss** | Функция потерь для нейросети: почти не учится на лёгких примерах (обычный трафик), фокусируется на трудных (редкие атаки) |
| **Precision / Recall** | Precision: из всех тревог сколько настоящих. Recall: из всех атак сколько поймали |
| **F1** | Среднее гармоническое precision и recall |
| **Macro-F1** | F1 по каждому классу, потом простое среднее. Редкий класс весит столько же, сколько частый |
| **PR-AUC** | Площадь под кривой precision-recall. Лучше ROC-AUC при дисбалансе |
| **MCC** | Коэффициент корреляции Мэтьюса: одна цифра качества, устойчивая к дисбалансу |
| **Утечка данных (leakage)** | Когда в признаках «подсказка» ответа (например IP атакующего). Модель кажется гениальной, но в реальности не работает. Мы удаляем IP, ID и время из признаков |
| **Валидация vs тест** | На валидации выбираем модель, на тесте один раз честно измеряем. Если выбирать по тесту, результат завышен |
| **Ансамбль (soft voting)** | Несколько моделей голосуют, усредняя вероятности |
| **LOF (Local Outlier Factor)** | Смотрит, насколько точка «одинока» по сравнению с ближайшими соседями. Учится только на нормальном трафике |
| **Isolation Forest** | Другой детектор аномалий: аномалии легко «отделить» случайными разрезами. У нас он оказался хуже LOF |
| **Concept drift** | Со временем данные меняются (атакующие меняют тактику), модель устаревает |
| **PSI** | Population Stability Index: насколько распределение признака сейчас отличается от прошлого. > 0.25 считается сильным сдвигом |
| **Leave-one-attack-out** | Убираем один тип атаки из обучения и проверяем, заметит ли его система как «новую угрозу» |
| **SOC** | Security Operations Center: команда, которая разбирает оповещения |
| **Triage** | Сортировка оповещений по важности: что разбирать первым |
| **Инцидент** | Группа оповещений одной атаки: тот же тип, общий узел (жертва DDoS, источник сканирования, C2-сервер ботнета), без пауз дольше часа |
| **Feedback loop / human-in-the-loop** | Цикл «модель → аналитик → разметка → дообучение модели». Человек исправляет ошибки, модель учится на исправлениях |
| **Active learning** | Человек размечает в первую очередь то, в чём модель меньше всего уверена: так каждая метка даёт больше пользы. Симулированный аналитик начинает с инцидентов «needs review» |
| **Alert fatigue** | «Усталость от оповещений»: когда их слишком много, аналитики пропускают важные. Группировка в инциденты борется именно с этим |

## 8. Если что-то не работает

| Проблема | Решение |
|---|---|
| `ModuleNotFoundError: nids` | Запускайте из папки проекта или выполните `pip install -e . --no-deps` |
| Интерфейс пишет «No trained model yet» | Сначала `python -m nids all` |
| Очень большой датасет, долго считается | В `configs/default.yaml` поставьте `data.max_rows: 500000` или `benchmark.max_train_rows: 200000` |
| Нет колонки времени | Эксперимент с дрейфом пропустится, остальное работает |
| Ошибка про длинный путь на Windows | Держите проект в коротком пути (как сейчас: `C:\Users\user\Projects\...`) |
